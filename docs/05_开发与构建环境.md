# Nodebuster 开发与构建环境

> 环境批次：`batch-4-dev-environment`<br>
> 目标平台：Windows x86_64<br>
> Godot：`4.2.2.stable.official.15073afe3`，标准版（非 Mono）<br>
> 原则：工具、缓存、测试存档、EXE、PCK 和构建日志不进入 Git

## 1. 当前可用状态

本批次建立了可重复的编辑与 Windows 导出链：

- 精确版本 Godot 编辑器和 console 启动器。
- Godot self-contained 模式，不污染系统级 Godot 配置。
- 匹配的 Windows x86_64 debug/release 导出模板。
- `project/export_presets.cfg` 中的 `Windows Desktop` x86_64 预设。
- `scripts/Setup-DevEnvironment.ps1` 可从官方 Release 重新部署工具。
- `scripts/Dev.ps1` 统一执行环境检查、导入、打开编辑器、运行、构建和固定帧冒烟测试。
- GodotSteam 的 GDExtension、debug/release DLL 与 `steam_api64.dll` 会由导出器自动收集。

修改 GDScript、场景和正常导出不需要 Visual Studio、MSVC、SCons 或 C++ SDK。只有需要重新编译 Godot 引擎或 GodotSteam 原生扩展时，才需要 C++ 工具链。

## 3. 快速使用

在仓库根目录执行：

```powershell
# 1. 检查引擎、模板、项目、预设和 GodotSteam
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Dev.ps1 doctor

# 2. 首次导入或资源变更后重新导入
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Dev.ps1 import

# 3. 打开 Godot 编辑器
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Dev.ps1 editor

# 4. 从源码运行，存档自动隔离
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Dev.ps1 run

# 5. 构建 Windows Release
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Dev.ps1 build -Configuration Release

# 6. 构建 Windows Debug
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Dev.ps1 build -Configuration Debug

# 7. 验证 Release 包可启动并运行 300 帧
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Dev.ps1 smoke -Configuration Release

# 8. 验证 Debug 包
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Dev.ps1 smoke -Configuration Debug
```

如果 Godot 不在默认位置，可使用：

```powershell
$env:NODEBUSTER_GODOT = "D:\path\Godot_v4.2.2-stable_win64.exe"
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Dev.ps1 doctor
```

也可以向 `Dev.ps1` 传递 `-GodotExe`。

## 4. 从零重新部署

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\Setup-DevEnvironment.ps1
```

脚本会：

1. 下载 Godot 4.2.2 Windows x64 标准版。
2. 下载官方 4.2.2 导出模板。
3. 对两个安装包执行固定 SHA-512 校验。
4. 解压编辑器并创建 `_sc_`。
5. 只安装 Windows x86_64 debug/release 模板。
6. 执行 `--version`，要求精确 build ID 匹配。

脚本不修改系统 PATH，也不安装系统级 Godot。可通过 `-InstallRoot` 指定其他便携位置。

## 5. 构建输出

默认输出位于被 `.gitignore` 排除的目录：

```text
build\windows\release\
build\windows\debug\
```

Release 构建应包含：

```text
Nodebuster.exe
Nodebuster.pck
libgodotsteam.windows.template_release.x86_64.dll
steam_api64.dll
```

Debug 构建对应使用 `libgodotsteam.windows.template_debug.x86_64.dll`，并额外生成便于查看输出的 `Nodebuster.console.exe`。

导出预设使用：

- `Windows Desktop`
- x86_64
- 分离式 PCK：`binary_format/embed_pck=false`
- 全部资源：`export_filter="all_resources"`
- 不修改模板 EXE 的资源：`application/modify_resources=false`
- 不签名：`codesign/enable=false`

`application/modify_resources=false` 避免引入 `rcedit`。因此当前开发构建可以稳定生成，但不会重写 EXE 的版本资源和图标。正式发布前可在独立批次安装 `rcedit`、启用资源修改并补代码签名。

## 6. Steam 与存档隔离

当前工程必须保留 GodotSteam 扩展。虽然 `MySteam.gd` 有离线门控，但仍有脚本直接引用 `Steam` 全局类；删除或禁用 GDExtension 会导致脚本无法解析。

`Dev.ps1 editor` 和 `Dev.ps1 run` 会把测试数据隔离到：

```text
.runtime\appdata\
.runtime\localappdata\
```

这些目录已忽略，不会触碰默认的 `%APPDATA%\Nodebuster` 正式存档。

当前 `ENFORCE_STEAM_OWNERSHIP=true`。发布构建仍保留 Steam 所有权规则；Steam 初始化不可用时进入离线/非 Steam 路径，跳过成就和回调。

## 7. 支持边界

当前只支持 Windows x86_64，因为仓库只包含该平台的 GodotSteam 实体库。不要添加 Win32、Linux 或 macOS 导出预设，除非先补齐对应 GDExtension 库并完成验证。

本环境可以生成可运行、可修改的恢复版构建，但不代表逐字节复现原 Steam 发布包：

- 原始 `export_presets.cfg` 已丢失，本批次使用重建预设。
- 尚未配置 `rcedit`、代码签名、Steam depot、Steamworks 上传或商店发布参数。
- 原始素材制作文件和完整第三方许可链仍不完整。
- EXE、PCK、TPZ、ZIP 和 `raw_pck/` 均不得提交到普通 Git 历史。

## 8. 常见故障

| 现象 | 处理 |
|---|---|
| Godot 版本不是精确 4.2.2 | 运行 `Setup-DevEnvironment.ps1` 或显式传入正确 `-GodotExe` |
| 提示缺导出模板 | 确认 `editor_data/export_templates/4.2.2.stable/` 中存在 Windows x64 模板 |
| `Steam` 未声明或 GDExtension 加载失败 | 检查 `.gdextension`、GodotSteam DLL 和 `steam_api64.dll`，不要禁用扩展 |
| 首次打开导入时间较长 | 等待 `.godot/` 缓存完成；该目录不提交 |
| 无错误的无界面导入/固定帧退出仍返回 `1` | 这是本机 Godot 4.2.2 Windows 自动退出路径的稳定现象；使用 `Dev.ps1 import/smoke`，脚本会结合日志、缓存和 GodotSteam 注册状态判定，真实错误仍会失败 |
| 导出目录不存在 | 使用 `Dev.ps1 build`，脚本会先创建目录 |
| 导出缺 DLL | 检查 `godotsteam.gdextension` 的 `[libraries]` 与 `[dependencies]` |
| 测试污染正式存档 | 通过 `Dev.ps1 editor/run` 启动；它们默认使用 `.runtime/` 隔离目录 |
