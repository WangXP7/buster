# 反编译与版本批次记录（Nodebuster RE）

> 本仓库对 Godot 4.2.2 发布的 Steam 游戏 **Nodebuster**（AppID 3107330）做逆向重建，
> 目标：让工程在 Godot 编辑器中**逐节点可视化、可编辑、可改可优化**。
> 所有修改按"批次（batch）"保留独立提交与 git tag。

---

## 1. 工程可编辑化路线

| 阶段 | 做法 | 产物 |
|------|------|------|
| 初版重建 | 从 `.pck` 解包 + 反编译 GDScript，但场景仍为二进制的 `.scn`（经 `.tscn.remap` 指针加载） | `project/`（仅 `.remap` 指针，无法直接编辑场景） |
| **场景反编译** | 用 **Godot RE Tools (GDRE) v2.6.0** 对原始 `Nodebuster.pck` 做整工程 `--recover`，把 39 个二进制 `.scn` 还原为文本 `.tscn` | `project/`（**39 个 `.tscn` 文本场景，0 个 `.remap`**，完全可编辑） |

GDRE 恢复命令（本机）：
```
gdre_tools.exe --headless \
  --recover="D:/REDACTED-DIR/Nodebuster/Nodebuster.pck" \
  --output="D:/REDACTED-DIR/_reverse_tools/gdre_recovered" \
  --ignore-checksum-errors
```
恢复日志关键结果：
- Detected Engine Version: **4.2.2**
- Verified / Extracted **645 files, no errors detected!**
- Imported resources for export session: 274 → Successfully converted: **274** / Lossy: **1** / Failed: **0**
- 提示：Use Godot editor version 4.2.2 to edit the project.

> 注：剩下那 1 个 "Lossy" 转换是某张被以有损方式导入的贴图（GDRE 只能还原其有损导入版本，无法还原原始无损源）。
> 它不影响在编辑器中打开与编辑场景，仅该贴图本身画质略低于原版。

---

## 2. 如何打开 / 编辑本工程

1. 安装 **Godot 4.2.2**（Forward+ / Mobile 渲染均可，工程 `project.godot` 用的是 `mobile` 渲染器）。
2. 用 Godot 打开 `project/` 目录。首次打开会重新导入资源（基于 232 个 `.import` 描述文件），生成 `.godot/` 缓存（已被 `.gitignore` 忽略，无需提交）。
3. Steam 相关：`addons/godotsteam` 已随工程恢复。`Scripts/Autoloads/MySteam.gd` 提供离线开关：
   - `ENFORCE_STEAM_OWNERSHIP = true`：仍强制 Steam 拥有校验（发布行为）。
   - 在 Godot 编辑器内直接运行 / 出 Standalone 包测试时，若无 Steam 单例会自动进入 **离线/非 Steam 模式**（仅跳过成就与回调），不会闪退。
   - 想完全禁用 Steam 初始化，可把该常量置 `false`。

## 3. 版本批次（git tag）

| tag | 批次 | 内容 |
|-----|------|------|
| `reconstructed-base` | batch-0 | 未修改的基础重建工程：反编译脚本 + 场景指针（`.remap`）。可阅读但场景不可直接编辑。 |
| `batch-1-steam-offline` | batch-1 | 修复 **BUG-13**：`MySteam.gd` 增加离线/非 Steam 分支（见 `docs/03_已知BUG与优化清单.md`）。 |
| `batch-2-scene-decompile` | batch-2 | **整工程场景反编译完成**：39 个 `.scn` → `.tscn`，0 个 `.remap`，工程完全可编辑。同时保留 batch-1 的 BUG-13 修复。 |

推送约定：每个批次单独提交并打 tag，统一 push 到 `origin/main`，以保留"不同修改批次的不同版本"。
